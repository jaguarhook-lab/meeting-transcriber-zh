# 錄音轉文字（meeting-transcriber-zh）

把會議錄音轉成逐字稿，校正人名和專有名詞後，整理成會議記錄（md 和 PDF）。Windows 視窗程式。

- 語音辨識用 [faster-whisper](https://github.com/SYSTRAN/faster-whisper) 在本機跑，CPU 就可以，錄音不會上傳。
- 校正畫面會列出可能聽錯的詞，可以播放那一段原音再決定怎麼改。改過的詞存成對照表，下次自動套用。
- 會議記錄交給你自己訂閱的 Claude Code 或 Codex 命令列工具寫，用的是訂閱額度，不需要 API 金鑰。
- 以繁體中文為主，也能辨識英文、日文或多語混合的會議。

## 下載

到 [Releases](https://github.com/jaguarhook-lab/meeting-transcriber-zh/releases/latest) 下載 `meeting-transcriber-zh-vX.Y.Z-win64.zip`，解壓縮後執行資料夾裡的 `錄音轉文字.exe`。只支援 64 位元 Windows，不用安裝 Python。

語音模型沒有包在裡面，第一次開啟時程式會帶你下載。想從原始碼執行，請看第十一節。

## 一、資料夾內容

解壓縮後約 0.3 GB：

```
錄音轉文字\
  錄音轉文字.exe
  _internal\            執行環境，不要動
  對照表.範例.tsv
  已知名詞.範例.txt
  情境說明.範例.txt
  README.md
  LICENSE
  THIRD_PARTY_NOTICES.md
```

用過之後會多出 `對照表.tsv`、`已知名詞.txt`、`設定.json`，這些是你自己的資料。整個資料夾可以直接複製到別台電腦或隨身碟。語音模型存在各台電腦上（見第三節），不在這個資料夾裡。

## 二、使用步驟

1. 開啟 `錄音轉文字.exe`。第一次會先跳出下載語音模型的視窗。
2. 選音檔（m4a、mp3、wav、mp4 等）和輸出資料夾。
3. 會議名稱預設是音檔檔名，可以改，輸出的檔案都以它開頭。
4. 「特別整理的主題」可以不填。填了的話，會另外整理一份這個主題的內容。
5. 確認設定區的 AI、語音模型、語言。
6. 按「① 開始辨識」。進度條會顯示預估剩餘時間。中途取消或關掉程式都沒關係，下次用同一個會議名稱再按一次，會從中斷的地方接著跑。
7. 辨識完會開啟「② 校正專有名詞」畫面。對照表裡的詞已經先換好，AI 會再列出疑似聽錯的人名、公司名和專有名詞，大約要幾分鐘。

   點一個詞，下方會列出它出現的句子。可以按「▶ 播放原音」聽前後約 12 秒，在「改為」填正確寫法後按「更新選取項目」。勾「加入共用對照表」，以後的錄音也會自動替換。

   - 同一個名字被辨識成好幾種寫法時，可以用 Ctrl 或 Shift 一次選多個，填一次「改為」就全部改好。
   - 填了「改為」就是替換；留空則是「待確認」，不替換，會列進 `<會議名稱>_待確認.md`。
   - 表格裡沒列到的錯字，用「＋手動新增」。多個錯誤寫法用頓號隔開，可以一次改成同一個寫法。
   - 本來就寫對的詞選「不改」，會議記錄裡就不會加（?）。再勾「加入清單」會存進已知名詞，以後不會再被列出來。

   改完按「套用並存檔」。
8. 按「③ 產生會議記錄」，大約幾分鐘。同一份逐字稿再產生一次時，新版會另存，不會蓋掉舊的。
9. 打開會議記錄 md，對照 `<會議名稱>_待確認.md` 修改，用記事本或 VS Code 都可以。

   記錄的順序是：會議資訊（日期、地點、主持人、記錄人、出席人員，聽不出來的留空）、重點摘要、各議題的背景／討論／決議／待辦、未決事項、待辦追蹤表。
10. 改完 md 按「重新產生 PDF」。md 裡的錄音時間點，例如（00:12:47–00:13:05），是方便回查錄音用的，PDF 不會印出來。
11. 按「從我的修改學習」，程式會比對原稿和你改好的 md，列出改過的詞，選擇要加進已知名詞或對照表，下次就不用再改一樣的錯。

    所有項目預設是「略過」，只把人名、公司名這類寫法的修正改成加入。數字、日期、金額的修改和補上去的文字不會列出來。「提醒」欄寫「需確認」的，表示抓不到完整的詞，請先把原寫法和改為修正好再加入。

## 三、語音模型

找不到模型時，程式會跳出下載視窗；之後也可以按「下載模型…」下載其他模型。

| 模型 | 大小 | 說明 |
|---|---|---|
| large-v3-turbo（建議） | 1.6 GB | 一般會議用這個。準確度接近 large-v3，速度快一倍以上。 |
| small | 0.5 GB | 最快，但人名、公司名錯字明顯較多，適合先看個大概。 |
| large-v3 | 3.1 GB | 最準，速度不到 turbo 的一半。錄音品質差時再用，記憶體最好 8 GB 以上。 |

在 i3-4160 的舊辦公電腦上，3 小時的錄音用 turbo 大約跑 4.3 小時。下載中斷的話，再按一次會接著下載。

程式依下列順序找模型：

1. `C:\Users\<帳號>\AppData\Local\錄音轉文字\models\`，下載的模型都放這裡。
2. 程式資料夾裡的 `models\`。要帶到沒有網路的電腦時，把模型複製到這裡。
3. 按「選擇模型資料夾…」指定的位置，網路磁碟也可以。

模型資料夾裡要有 `model.bin`、`config.json`、`tokenizer.json` 和 `vocabulary.json`（或 `vocabulary.txt`），缺檔時程式會告訴你缺哪些。其他 faster-whisper 格式的模型也能用，可以在 Hugging Face 搜尋「faster-whisper」。

## 四、語言

| 選項 | 說明 |
|---|---|
| 中文（繁體輸出） | 預設。輸出繁體中文，夾雜的英文術語照原樣保留。 |
| 英文、日文 | 整場都講英文或日文時用。 |
| 自動偵測 | 依錄音開頭判斷，整場當同一種語言。 |
| 多語混合 | 每一段分開判斷，適合輪流講不同語言的會議。比較慢，短句容易判錯。 |

同一個模型就涵蓋約 99 種語言，不用另外裝語言包。只有中文會做簡轉繁。

## 五、AI（Claude Code／Codex）

在設定區選要用哪一個，程式會記住。紀錄區和待確認清單都會註明這次是哪一個 AI 整理的。

錄音檔不會送出去，送給 AI 的只有文字：

| 步驟 | 送出的內容 |
|---|---|
| ② 找疑問詞 | 校正前的逐字稿、情境說明、已知名詞 |
| ③ 會議記錄、專題 | 校正後的逐字稿、情境說明、已知名詞、這次確認過和待確認的詞 |

情境說明和已知名詞如果有公司或個人資料，請先確認可以交給該 AI 服務處理。

| 按鈕 | 作用 |
|---|---|
| 登入帳號 | 開一個視窗登入，會跳出瀏覽器。Claude Code 已登入時，可以在視窗輸入 `/login` 換帳號，`/exit` 離開。 |
| 查看用量 | 開啟該 AI 的用量網頁。 |
| 安裝說明 | 顯示安裝指令，可以複製。 |

程式一律用你的訂閱帳號：Claude Code 用 claude.ai 帳號，Codex 用 ChatGPT 帳號。呼叫時會拿掉 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 環境變數，所以不會改走 API 另外計費。3 小時的會議大約 8 萬字，找詞和寫記錄都會用掉不少額度。

用到上限時，畫面上方會出現紅色提示，寫著預計幾點恢復。另一個 AI 有安裝的話，可以直接改用它重試。錯誤訊息沒寫恢復時間時會顯示「恢復時間不明」，可以按「查看用量」到網頁上看。辨識和校正都已經存檔，恢復後再按一次就好。

## 六、安裝 AI 命令列工具

換電腦時要裝一次，不需要 VS Code。兩個至少裝一個；都沒裝的話，還是可以辨識、用對照表和手動新增來校正、重新產生 PDF。

### Claude Code

1. 沒有 Git 的話，先安裝 Git for Windows：https://git-scm.com
2. 在 PowerShell 執行：

   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```

   已經有 Node.js 18 以上的話，也可以用：

   ```powershell
   npm install -g @anthropic-ai/claude-code
   ```

3. 重開 PowerShell，在程式按「登入帳號」（或在 PowerShell 輸入 `claude`），用 claude.ai 帳號登入。
4. 更新用 `claude update`，不行的話執行 `npm install -g @anthropic-ai/claude-code@latest`。

### Codex

1. 安裝 Node.js 18 以上的 LTS 版：https://nodejs.org
2. 在 PowerShell 執行：

   ```powershell
   npm install -g @openai/codex
   ```

3. 在程式按「登入帳號」（或輸入 `codex login`），用 ChatGPT Plus 以上的帳號登入。
4. 更新時再執行一次安裝指令。

裝好後在程式切換到該 AI，會顯示「● 已安裝」。沒有的話，重開程式。

## 七、輸出的檔案

| 檔案 | 說明 |
|---|---|
| `<會議名稱>_逐字稿.txt` | 校正後的逐字稿，每行開頭有時間 |
| `<會議名稱>_會議記錄.md`、`.pdf` | 會議記錄 |
| `<會議名稱>_待確認.md` | 給整理的人核對用：標了（?）的詞、要回去聽錄音的地方。不轉 PDF。 |
| `<會議名稱>_<主題>_專題整理.md`、`.pdf` | 有填主題才會有 |
| `_工作檔\<會議名稱>\` | 16k 音檔、原始辨識結果、校正紀錄、進度、會議記錄原稿 |

輸出資料夾已經有同名檔時，會另存成 `(2)`、`(3)`，重新產生 PDF 也一樣，不會蓋掉舊檔。

AI 回覆的格式不對時（例如沒把待確認清單分開），不會產生 PDF，紀錄區會提示，完整回覆在 `_工作檔\<會議名稱>\會議記錄_原始回覆.md`。

`_工作檔` 裡的音檔比較大，3 小時約 330 MB。記錄定稿後可以搬走或刪掉，只是刪了就不能續跑或播放原音。

## 八、對照表（對照表.tsv）

第一次使用時，程式會從 `對照表.範例.tsv` 複製一份 `對照表.tsv`。每行一筆，「原辨識」和「校正為」中間用 Tab 隔開，`#` 開頭是註解。存檔請用 UTF-8。

每次辨識完都會自動套用。校正畫面勾了「加入共用對照表」的詞，會加在檔案最後面。替換是看到就換，太短或太常見的詞不要放，免得換錯。換電腦時記得把這個檔一起帶走。

## 九、情境說明與已知名詞

### 情境說明（情境說明.txt）

第一行用一句話描述會議類型，會放進語音辨識和找詞的提示，讓專有名詞辨識得更準。第二行以後可以寫背景，例如公司之間的關係、常出現的角色，給找詞和寫記錄的 AI 參考：

```
一場會計師事務所的週會，討論稅務申報、查帳與客戶進度
本公司是「範例會計師事務所」，文中的「我們」「我方」指本公司。
「大華公司」是主要客戶，聯絡窗口是王經理。
```

可以參考 `情境說明.範例.txt` 自己建一份。沒有這個檔的話，會用「一場公司內部會議」。

### 已知名詞（已知名詞.txt）

寫法確定正確的人名、公司名、產品名、地名。一行一筆，格式是「名詞｜說明｜常被誤寫成」，後面兩欄可以省略：

```
王小明｜業務部經理｜王曉明、黃小明
範例股份有限公司｜主要客戶
```

AI 找疑問詞時會跳過這些詞，寫記錄時也不會加（?）。「說明」會一起給 AI，讓它知道這個人或公司是做什麼的。「常被誤寫成」跟對照表一樣，辨識完會自動換掉。

主畫面按「編輯已知名詞」可以用記事本修改；「從我的修改學習」和校正畫面的「不改＋加入清單」也會加進來。第一次使用時會從 `已知名詞.範例.txt` 複製一份。

## 十、環境檢測

換電腦後可以先檢查一下。在程式資料夾開 PowerShell：

```powershell
.\錄音轉文字.exe --檢測 "某個短音檔.m4a" "C:\暫存\檢測"
```

會依序測試辨識、兩個 AI 和轉 PDF，結果寫在 `C:\暫存\檢測\環境檢測.log`，最後一行是「全部完成」就沒問題。要先開過程式把語音模型下載好。

## 十一、從原始碼執行、自行打包

需要 Windows 和 Python 3.10 以上。

```powershell
git clone https://github.com/jaguarhook-lab/meeting-transcriber-zh.git
cd meeting-transcriber-zh
python -m pip install -r requirements.txt
python app.py      # 執行
python build.py    # 打包到 dist\錄音轉文字\
```

`build.py` 會把本機的對照表、情境說明、已知名詞一起放進打包資料夾。要把打包版給別人或公開之前：

1. 刪掉 `對照表.tsv`、`已知名詞.txt`、`情境說明.txt`、`設定.json`，只留範例檔。
2. 刪掉 `_internal\` 下各 `*.dist-info\` 裡的 `__pycache__\`，裡面可能有打包電腦的使用者路徑。
3. 搜尋一遍，確認沒有公司名稱、人名或本機路徑，再壓縮。

| 檔案 | 內容 |
|---|---|
| `app.py` | 視窗與流程 |
| `asr.py` | 語音辨識、模型下載 |
| `engines.py` | 呼叫 Claude Code／Codex、登入、使用上限 |
| `terms.py` | 對照表、專有名詞校正 |
| `learn.py` | 從我的修改學習 |
| `report.py` | 會議記錄與專題的提示詞 |
| `pdf.py` | Markdown 轉 PDF |
| `common.py` | 路徑、設定、已知名詞、情境說明 |
| `build.py` | 打包 |

## 十二、其他

- 轉 PDF 用程式內建的 PyMuPDF，不需要瀏覽器。字型用 Windows 內建的微軟正黑體，沒有的話用新細明體。
- 錄音不會區分是誰在講話，記錄裡用職務或角色稱呼，例如主持人、會計。
- 程式碼採 MIT 授權（見 `LICENSE`）。打包版內含以 AGPL-3.0 授權的 PyMuPDF，各版本的完整原始碼就是本專案同名的標籤（例如 `v1.1.2`）。第三方套件的授權見 `THIRD_PARTY_NOTICES.md`，自行打包散布時也要遵守。
- 本程式與 Anthropic、OpenAI 無關。Claude Code、Codex 是兩家公司各自的產品，使用時請遵守它們的服務條款。

本程式在 Claude 協助下製作。
